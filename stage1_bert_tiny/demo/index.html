Phishing detector — demo pages

Six static pages for exercising the extension by hand: two that imitate credential-harvesting pages, two that reproduce a webmail client with a phishing message open, and two ordinary pages. The verdicts below were measured with the shipped model on the exact text the extension extracts from each page.

These pages must be served over HTTP. Opening them with file:// will not work: the content script only matches http://*/* and https://*/*, and the popup refuses to scan any page that is not http or https. 
cd phishing-project
.venv/Scripts/python.exe -m http.server 8000 --bind 127.0.0.1

The --bind 127.0.0.1 keeps the server on the loopback interface, so the project folder is not exposed to your local network. Then open http://127.0.0.1:8000/demo/index.html and click the extension icon on each page.

phishing-login.html phishing 0.998
phishing-invoice.html phishing 0.997

webmail-iframe.html phishing 0.995
legit-article.html legitimate 0.170
legit-shop.html legitimate 0.045

webmail-lookalike.html and webmail-iframe.html are the interesting ones. The first puts a sidebar, a search bar and a toolbar before the message, the way a real webmail client does. The extension originally took the first 1,500 characters of the page's text, which on a page shaped like this is the sidebar — so a phishing email was classified as legitimate. It now collects the page's prose and skips links and navigation. The second puts the same message inside an iframe, which the extension could not read at all until it was taught to look in same-origin frames. Both exist as regression fixtures for those two bugs.

Neither page reproduces the real cause of that failure, though, because it was not in the extractor at all. The model was being sent [url], [title] and [body] together, and its training corpus contains no such document — only [url]+[title] for URL pages and [from]+[body] for emails. So a Gmail page's own URL and title made it classify the mail client instead of the message. A webmail client's URL describes the client, not the mail, which is why the extension now omits it there.

None of these pages contains a form that submits data, a script, or any network request. The four lookalikes are inert text used only as input to the classifier.
